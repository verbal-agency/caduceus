# Cycle handoff — G02 implement the workflow state machine

**Status:** complete.

## Goal boundary

G02 adds independently enforceable workflow state for cases. It introduces the
source-defined `CaseState` enum, an explicit allowed-transition table,
immutable state snapshots, a deterministic transition function, and a
service-mediated write boundary. It does not add payer calls, authorization
policy, persistence hardening, human-review UI, HTTP endpoints, or agent
behavior.

## Test-first evidence

`tests/test_workflow_state_machine.py` was added before `caduceus.workflow`
existed and initially failed during collection with `ModuleNotFoundError`. The
implementation then added the smallest workflow module needed to satisfy the
declared state vocabulary, allowed transitions, invalid-transition behavior,
and service boundary.

## Decisions and routed findings

- The transition graph is intentionally minimal and administrative: cases move
  from intake to investigation, missing-information loops, review, submission,
  payer pending/result states, escalation, and closure.
- `Case` remains a G01 wire contract without embedded mutable state. G02 stores
  state in a separate `WorkflowStateRecord`, preserving the distinction between
  case identity and workflow write authority.
- Concurrency control remains in-memory and non-durable. This is already routed
  by the roadmap to the future storage/persistence goal rather than expanded
  into G02.
- No new backlog item or roadmap reordering is required.
